# Apollo 2.0.7 (107)

Ships PR #8 (Gabriel, a pedido da Joana): remove a file from the send flow before sending (the "x" on each file, "Adicionar mais" that adds instead of replacing the list, and "Ajustar vídeos" that discards a prepared batch and returns to the choices), plus a trash button on videos already sent. ClickUp's public API cannot delete attachments, so a removal drops the whole lineage from the Apollo media manifest for everyone, deletes the Apollo REVISAR comment that carries only that video, and leaves the file in the ClickUp attachments. The manifest gains optional `removedAttachmentIds`, `removedLineageIds` and `removedAssetIds`.

`swift test -Xswiftc -DAPOLLO_TASKS_REACT -Xswiftc -DAPOLLO_AGENDA_REACT -Xswiftc -DAPOLLO_BOARD_REACT --no-parallel` on the PR head (tree identical to merge `0afe968`) passed 274 XCTest tests (4 skipped, 11 new in `TaskMediaRemovalTests`) and 33 Swift Testing tests. A production-identity build (`com.painellunar.app`) launched and loaded real data (134 tasks). The trash, "Ajustar vídeos" and a removal against real ClickUp were not driven by automation (no screen control in the session) and were not exercised against ClickUp.

Known follow-ups from review: builds before 2.0.7 decode the manifest without the removal lists and drop them when they re-upload it, so a send from an old build on the same task brings removed videos back; `TaskDetailView.displayedAttachments` reads the catalog through `catalog(for:)`, which can hit disk during render.
